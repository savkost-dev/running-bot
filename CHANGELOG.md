## [0.42.14] 2026-10-07 — /test_long: прогресс как облегчённый ровный, шкала одной горкой

### Изменено
- **`long_ai.PROMPT_LONG_AI`** — раздел «Нагрузка вариантов»: лесенка по нагрузке монотонна (N ровно < N-прогресс < (N−1) ровно); прогресс = ровный вариант следующей группы с мягкой первой половиной; если по силам (N−1) ровно, то N-прогресс по силам тем более. Из правил фона убраны «прогресс только при хорошей готовности / низкой нагрузке». В описании `suitability_percentages`: проценты одной горкой по скорости, вариант с плюсом не ниже обоих соседей.
- **`long_ai.LONG_TYPE_NOTES`** — пояснение типа II: «ровный вариант следующей группы с мягкой первой половиной: тот же темп второй половины бежится свежее».
- Причина (Антон): на прогоне по сильному бегуну шкала шла пилой 70/25/95/35 — все варианты с плюсом получали низкий процент из-за запрета прогресса при средней готовности.

## [0.33.0] 2026-10-02 — Разбор: кнопка «без отсечек», нарезка по плану

### Добавлено
- **`ai_package._cut_by_plan`** — нарезка записи по плану без отсечек часов: от старта первого рабочего круга (после `_drop_extra_first_lap`) посекундный ряд режется по длинам шагов в порядке исполнения (`strava._expand_plan_roles`), граница шага — интерполяция по накопленной дистанции. Отдых по расстоянию режется как обычный шаг; если ряд кончился раньше плана, последний шаг берётся по фактически пройденному (не короче 100 м). Поля круга (ЧСС, каденс, мощность, NP, GCT, ВК, дыхание) — средневзвешенные по перекрытию во времени с исходными кругами, максимум ЧСС — максимум по ним.
- **`ai_package._can_cut_by_plan`** — кнопка предлагается только при посекундном ряде с достоверной дистанцией (GPS или Stryd; «без GPS без Stryd» — нет), известном старте первого круга, плане целиком по дистанции и без задания в часах.
- **`ai_package.build_package(cut_by_plan, cand)`** — параметры нарезки и готового кандидата; в результате `can_cut`, `cut_by_plan`, `cand`. В пакете для ИИ строка «Разметка отрезков: по плану …». Кандидаты всех трёх источников несут `plan_wkt`.
- **`bot.report_cut_callback`** (`report_cut:<s|f>:<db_user_id>:<act_id>`) — кнопка «✂️ Без отсечек — нарезать по плану» под готовым разбором (над «Оценить разбор» / «Главное меню»); после нарезки кнопка не повторяется. Кандидат берётся из `user_data["report_cand"]` прошлого разбора — в сервисы заново не ходим (дневной лимит FIT у COROS, квота streams у Strava); если кэш потерян (перезапуск), тренировка добывается по activityId. Чужой разбор — только админу.
- **`ai_package.build_report_card(cut_by_plan)`** — пометка «без отсечек» в шапке карточки.

### Причина
- 02.10.2026, DD_20261002-3 (1 км + 3 км + 1 км слитно, Stryd, автокруги по 1 км, без задания в часах): с часов пришло 8 кругов (996, 1000, 1000, 1000, 54, 1000, 4, 26 м); разметка «один круг = один шаг» показала «3 км» как один километр 4:04 и потеряла финальный быстрый километр. С нарезкой: 1000 м 3:47, 3000 м 4:06, 1000 м 3:52.

Отложено (после этого пункта): кнопка «пропустить N первых кругов» со значением 0 по умолчанию.

## [0.17.0] 2026-05-30 — quality_volume: интеграл качественной работы

### Изменено (recommend_group, borderline)
- Связка completability × стимул заменена единым физиологическим показателем **quality_volume = intensity × time_to_termination** (накопленный объём качественной работы до отказа), нормированным к [0..1]
- `intensity(pace)` — относительная интенсивность (скорость^exp к порогу), растёт с темпом
- `time_to_termination(pace, rec)` — доля времени, удерживаемая бегуном: плато ниже порога, излом на пороге, резкий нелинейный обрыв выше (накопление лактата); усталость приближает грань
- Кривая имеет **максимум у порога**: слишком медленно → интенсивности нет, слишком быстро → времени работы нет
- Итог: `% = полезность_зоны(характер×спец) × quality_volume`
- Метки из положения на кривой: оптимум / «тяжело, но реально» / «риск схода/травмы, мало времени работы» / «низкий стимул, мало интенсивной работы» / «разгрузочный вариант на сегодня» (при плохом восстановлении)
- На плохом восстановлении грань отказа ближе → разгрузочные (медленнее порога) группы поднимаются, оптимум может смещаться к 3-4
- Константы `_INTENSITY_EXP`, `_TTT_TAU`, `_TTT_STEEP`, `_TTT_RECOVERY_K` — для калибровки по фактам тренировок
- `is_borderline=false` и long — логика не применяется

## [0.16.6] 2026-05-30 — Завершаемость как множитель (калибровка %)

### Изменено (recommend_group, borderline)
- **% = полезность_зоны × completability** — завершаемость стала МНОЖИТЕЛЕМ (необходимое условие), а не слагаемым. Не дотянет → % низкий при любой ценности зоны
- `completability` — нелинейная функция от того, насколько темп быстрее персонального порога (ЛП/эквивалент): у порога ≈1.0, за гранью посильного крутой обрыв (`1/(1+(Δ/D0)^k)`, D0=31, k=3). Запредельные группы падают в одноразрядные % (баг 57% → ~10%)
- Характер-speed ослаблен: полезность зоны = floor 0.8 + 0.2·(характер×спец) — тилт мягкий, завершаемость важнее соответствия зоне; больше не тянет в непосильную группу ради «правильной зоны»
- Восстановление корректирует completability (уставший → грань завершаемости ближе, `_REC_FATIGUE_K`)
- Метки завершаемости в подаче: «тяжело, но реально / перебор, на грани / запредельно / риск схода»
- Пороги/коэффициенты в константах (`_USEFULNESS_FLOOR`, `_COMPL_D0`, `_COMPL_K`, `_REC_FATIGUE_K`) для калибровки по /ratings
- `is_borderline=false` — без изменений (по чистой форме)
