## [0.24.45] 2026-06-06 — скоростной паспорт k100, формула критической скорости

### Изменено
- **zones.py `_compute_speed_passport`**: заменил `_compute_sprint_ceiling`. Возвращает `(k100, runner_profile)`: gap>30→0.55 скоростной, 15-30→0.64 универсал, <15→0.73 выносливостный.
- **zones.py `speed_ceiling_for_distance`**: новая публичная функция. Формула: `k(d)=1-(1-k100)×(400-d)/(3×d)`, `ceiling=MSS(d)/0.94`. Работает для 100-400м.
- **zones.py `get_pace_zones`**: теперь возвращает `speed_k100` и `runner_profile` (вместо `sprint_ceiling`).
- **bot.py `_build_variant_b_prompt`**: из `analysis.structure` собирает скоростные блоки (≤200м, recovery>work или purpose содержит "скорост"/"нейромышечн"). Для каждой уникальной дистанции вычисляет потолок через `zones.speed_ceiling_for_distance`.
- **claude_advisor.py `build_ai_b_prompt`**: параметр `speed_ceilings: list|None`. Один блок → краткая строка; несколько — перечень по блокам с правилом "каждый не превышает свой потолок".

## [0.24.43] 2026-06-06 — _sprint_ceiling: потолок финишного темпа в промпте B

### Добавлено
- **claude_advisor.py `_sprint_ceiling`**: вычисляет MSS150 (макс. скорость на 150м) из зон бегуна. Коэффициент k зависит от gap threshold−repetition: >30 сек → 0.75 (скоростной), 15–30 → 0.80 (универсал), <15 → 0.85 (выносливостный). Рабочий потолок = MSS150 / 0.95.

## [0.20.4] 2026-05-31 — Двухцветная шкала: alt_pct отвязан от усталости

### Исправлено
- `alt_pct` (% для альтернативной цели) больше **не умножается на qvnorm** → не давится сегодняшней усталостью и завершаемостью

## [0.17.0] 2026-05-30 — quality_volume: интеграл качественной работы

### Изменено (recommend_group, borderline)
- Связка completability × стимул заменена единым физиологическим показателем **quality_volume = intensity × time_to_termination** (накопленный объём качественной работы до отказа), нормированным к [0..1]
- `intensity(pace)` — относительная интенсивность (скорость^exp к порогу), растёт с темпом
- `time_to_termination(pace, rec)` — доля времени, удерживаемая бегуном: плато ниже порога, излом на пороге, резкий нелинейный обрыв выше (накопление лактата); усталость приближает грань
- Кривая имеет **максимум у порога**: слишком медленно → интенсивности нет, слишком быстро → времени работы нет
- Итог: `% = полезность_зоны(характер×спец) × quality_volume`
- Метки из положения на кривой: оптимум / «тяжело, но реально» / «риск схода/травмы, мало времени работы» / «низкий стимул, мало интенсивной работы» / «разгрузочный вариант на сегодня» (при плохом восстановлении)
- На плохом восстановлении грань отказа ближе → разгрузочные (медленнее порога) группы поднимаются, оптимум может смещаться к 3-4
- Константы `_INTENSITY_EXP`, `_TTT_TAU`, `_TTT_STEEP`, `_TTT_RECOVERY_K` — для калибровки по фактам тренировок
- `is_borderline=false` и long — логика не применяется

- Вывод: основная группа (макс %), альтернативы с условием по цели («60% для полумарафона, но 90% если цель скорость»)
- `is_borderline=false` → «группа по силам N» без альтернатив по качествам
- Специализация показывается в выводе (пометка если по умолчанию); дефолт half_marathon
- Интеграция в /workout и автозапуск анализа — отдельно позже

## [0.5.0] 2026-05-25 — Data pipeline, Garmin JSON, smart cache

### Добавлено
- **Garmin workout JSON** — DeepSeek генерирует готовый JSON тренировки прямо в основном промте (единственный API-вызов, нет отдельного запроса)
- **48h нагрузка** — `get_recent_48h_load` в Strava: количество тренировок, км и страдание за последние 48 ч; учитывается в вечернем промте
- **Smart Garmin cache** — динамичные метрики (Readiness, Body Battery, HRV) всегда свежие; статичные (VO2max, Training Status) запрашиваются раз в 24 ч
- **Планировщик 01:00 UTC** — `scheduled_strava_cache` обновляет CTL/ATL/TSB и Riegel-предсказания для всех пользователей
- **Fast mode по умолчанию** — `ai_mode DEFAULT 'fast'` в БД; уведомление о режиме в вечернем сообщении
- **Global error handler** — тихо поглощает `BadRequest: Message is not modified` (двойной клик) и сетевые ошибки

### Исправлено
- Кнопки Garmin (скачать/загрузить FIT) не появлялись после нажатия кнопки `get_workout` — теперь `button_handler` передаёт `msg` в `_send_workout_recommendation`
- "Думающее" сообщение не показывалось при вызове через кнопку (только при `/workout`)
- FIT-генератор: темп в формате `M.SS` (точка вместо двоеточия) не распознавался → добавлен regex `r'\b([3-7]\.\d{2})\b'`
- FIT-генератор: `2:17–2:10` интерпретировалось как темп (7.3 м/с) → проверка >5.5 м/с → перевод как время на дистанцию
