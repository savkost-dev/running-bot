## Версионность

### Схема: MAJOR.MINOR.PATCH

| Тип изменения | Пример | Версия |
|---|---|---|
| Критическая архитектура | новая БД, смена AI провайдера | MAJOR (X.0.0) |
| Новая фича | новый источник данных, новая команда | MINOR (0.X.0) |
| Баг-фикс, мелкий твик | правка промта, исправление парсера | PATCH (0.0.X) |

1. Обновить `src/version.py` (VERSION, BUILD_DATE, CHANGES)
2. Добавить запись в `CHANGELOG.md`
3. Задеплоить: `.\deploy.ps1`

## Архитектура рекомендации (двухшаговая)

### Шаг 1 — Анализ анонса (`analyze_workout`)
- Запускается автоматически при появлении нового поста в канале DD (`scheduled_new_workout_check` каждые 30 мин)
- Модель: `deepseek-v4-pro` (всегда deep, режим меняет только `/preprocess_mode`)
- Результат сохраняется в `workout_analysis` (SQLite), используется всеми пользователями
- Ключевые поля результата:
  - `summary` — суть тренировки (1-2 предложения)
  - `overall_purpose` — что развивает тренировка в целом
  - `what_to_watch` — типичные ошибки, на что обратить внимание
  - `structure[]` — блоки работы (reps, дистанции, purpose)
  - `groups[]` — темпа каждой группы по блокам (`work_pace_start`, `work_pace_end`, `work_distance_m`)
  - `is_borderline` — дают ли группы разные физиологические качества
  - `coach_notes` — общие уточнения для всех

### Формат темпов (критично!)
- `work_pace_start` — темп первого (медленного) отрезка при прогрессии
- `work_pace_end` — темп последнего (быстрого) отрезка; если прогрессии нет → start == end
- `work_distance_m` — длина рабочего отрезка в метрах
- `_group_primary_pace()` усредняет start+end для определения зоны пользователя

### Шаг 2 — Рекомендация (`recommend_group` / `recommend_long`)
- Запускается под каждого пользователя при `/workout`, `/long` или вечерней рассылке
- Берёт готовый анализ из кэша + персональные зоны пользователя + данные восстановления
- Формулы считают: зону каждой группы, % подходимости, основную группу, альтернативы
- ИИ (режим из `/mode`) генерирует только прозу-обоснование поверх чисел
- `recommendation_to_advice()` → advice-dict для `format_evening_message()`

### Структура вечернего сообщения
```
Шапка (дата, место, расписание, погода)
━━━━━━━━━━━━━━━
💡 Суть           ← analysis.summary (дословно из Шага 1)
🏁 Цель тренировки ← analysis.overall_purpose (дословно из Шага 1)
━━━━━━━━━━━━━━━
📊 Подходимость групп (шкала 🟩/🟦)
━━━━━━━━━━━━━━━
🎯 Группа X — темп
   <обоснование от ИИ>
⚡ Активное восстановление (если active_recovery)
Оцени на разминке (🟢 легко / 🔴 тяжело)
━━━━━━━━━━━━━━━
Подготовка (coach_notes + what_to_watch)
Предупреждения
Футер (время Шага 2, режим, токены, версия)
```

## Ключевые технические детали

### AI модели (DeepSeek)
- `MODEL_DEEP = "deepseek-v4-pro"` — Шаг 1 (анализ анонса) + режим deep
- `MODEL_SMART = "deepseek-v4-flash"` — режимы smart/fast/calc (Шаг 2)

### Режимы рекомендации (`/mode`, только Шаг 2)
| Режим | Модель | Время | Описание |
|---|---|---|---|
| 🧠 deep | deepseek-v4-pro | ~2 мин | Максимальное качество прозы |
| ⚡ smart | deepseek-v4-flash | ~30-60 сек | Баланс (дефолт) |
| 🪶 fast | deepseek-v4-flash | ~10 сек | Короткое объяснение |
| 📊 calc | deepseek-v4-flash | формулы | Только числа + короткий текст |

### Источники данных (приоритет)
**Фитнес**: Garmin → COROS → Polar → Strava
**Восстановление**: Whoop → Garmin → COROS → Polar

### Зоны пользователя (`zones.py`)
- Считаются из VO2max + лактатный порог
- Хранятся в БД, пересчитываются при обновлении профиля
- Зоны: easy / marathon / threshold / interval / repetition

### Шкала подходимости (borderline)
- `pct` = полезность_зоны × quality_volume (по силам сегодня, цель пользователя)
- `alt_pct` = чистая ценность зоны для альт-специализации (без qvnorm)
- Двухцветная: 🟩 основная цель, 🟦 альтернативная цель (если разница ≥ 12%)

## Обработка ошибок

- `BadRequest: Message is not modified` — двойной клик по кнопке, молча игнорируется
- `TimedOut`, `NetworkError` — логируются как warning, не как error
- Все остальные — `logger.error` с traceback + сообщение пользователю
