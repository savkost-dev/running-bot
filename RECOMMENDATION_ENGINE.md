# DoDick Bot — Движок рекомендаций: формулы и алгоритм

> Описание расчёта % подходимости групп (Шаг 2, recommend_group для interval).
> Источник истины — `claude_advisor.py`, строки ~840-1230. Этот документ объясняет логику.
> Версия формул: 0.20.5. Последнее обновление: 01.06.2026.

---

## Главная идея

Для каждой группы тренировки считается **% подходимости** — насколько эта группа
полезна конкретному бегуну с учётом его формы, восстановления и цели.

```
% подходимости = usefulness × quality_volume × 100
```

Два множителя с разными ролями:
- **quality_volume** (0..1) — ГЛАВНЫЙ фактор. Сколько качественной работы бегун
  реально выполнит в этой зоне. Физиология: и развивает, и добежит.
- **usefulness** (floor..1.0) — МЯГКИЙ тилт. Насколько зона ценна под цель/характер
  тренировки. Не главный, лишь смещает приоритет среди посильных групп.

Принцип: **завершаемость важнее зоны.** Лучше недооценить и добежать чисто, чем
переоценить и сойти. Поэтому quality_volume доминирует, а usefulness — гентл-поправка.

## Множитель 1: quality_volume (физиологическое ядро)

```
quality_volume = intensity(pace) × time_to_termination(pace, recovery)
```

Это «интеграл интенсивности по времени до отказа» — сколько качественной работы
накопится за тренировку. Имеет МАКСИМУМ у лактатного порога:
- слишком медленно → intensity ≈ 0 (нет стимула)
- слишком быстро → time_to_termination ≈ 0 (сойдёшь раньше)
- у порога с лёгким заходом выше → оптимум

### intensity(pace) — интенсивность темпа (асимметричная, с 0.20.5)
```python
ratio = thr_sec / pace_s
if ratio <= 1.0:                          # у порога или медленнее
    intensity = ratio ** _INTENSITY_EXP   # степенной спад
else:                                     # быстрее порога
    intensity = 1.0 + (ratio - 1.0) ** 0.5  # корневой рост (медленнее насыщается)
```
- `thr_sec` — лактатный порог бегуна (сек/км), `pace_s` — темп группы (сек/км)
- = 1.0 на пороге; ниже порога — резко падает (степень 4); выше порога — растёт медленно (корень)
- `_INTENSITY_EXP = 4.0` — крутизна спада ниже порога
- **Зачем асимметрия:** степенной рост выше порога (старая формула) завышал quality_volume
  у скоростных групп, уводя их в топ. Корневой рост правильно моделирует физиологию:
  выше порога каждый доп. сек/км не даёт пропорционального прироста «стимула».

### time_to_termination(pace, recovery) — доля времени, которую удержишь (0..1)
```python
delta = thr_sec - pace_s                                  # >0 = быстрее порога
if delta <= 0:  return 1.0                                 # у порога/медленнее — держишь всё
eff = delta * (1.0 + (1.0 - rec) * _TTT_RECOVERY_K)        # усталость приближает грань
ttt = 1.0 / (1.0 + (eff / _TTT_TAU) ** _TTT_STEEP)
```
- Ниже порога — ПЛАТО (лактат в равновесии, держится долго, ttt≈1)
- Выше порога — РЕЗКИЙ нелинейный обрыв (накопление лактата → отказ)
- `_TTT_TAU = 28` — превышение порога (сек/км), где ttt падает до ~0.5
- `_TTT_STEEP = 5.5` — крутизна обрыва (было 3.8 → острее, гр2 МПК delta=24 → ttt≈0.57)
- `_TTT_RECOVERY_K = 0.35` — поправка на восстановление: уставший (rec→0) → грань
  отказа ближе, та же зона становится тяжелее

**rec** — восстановление 0..1 (из Garmin Readiness / Whoop Recovery / HRV / сон).

## Множитель 2: usefulness (тилт под цель/характер)

```python
usefulness = _USEFULNESS_FLOOR + (1.0 - _USEFULNESS_FLOOR) * spec_component
```
- `_USEFULNESS_FLOOR = 0.72` — нижняя граница (диапазон 0.72..1.00)
- Спец влияет заметнее чем при 0.80 → alt_pct отрывается от pct, альтернативы видны

### spec_component — ценность зоны под бегуна
```python
char_v = _CHARACTER_ZONE[character][zone]          # что тренировка СПОСОБНА дать
base   = _SPEC_ZONE_VALUE[spec][zone]              # приоритет под специализацию
spec_component = char_v * (0.6 + 0.4 * base)
```
**Характер доминирует** (0.6 базовый + 0.4 от спец): зону, которую тренировка не
тренирует, под любую цель ценим низко. Специализация лишь тилтит приоритет среди
того, что тренировка реально даёт.

### character — характер тренировки (по длине отрезков + ключевые слова)
- `speed` — короткие быстрые (≤400м)
- `vo2` — средние интервалы (≤1000м)
- `tempo` — длинные/пороговые (>1000м)

### Таблица _CHARACTER_ZONE (что тренировка развивает, 0..1)
| character | repetition | interval | threshold | marathon | easy |
|-----------|-----------|----------|-----------|----------|------|
| speed     | 1.00      | 0.90     | 0.50      | 0.25     | 0.10 |
| vo2       | 0.70      | 1.00     | 0.80      | 0.40     | 0.15 |
| tempo     | 0.30      | 0.60     | 1.00      | 0.90     | 0.40 |

### Таблица _SPEC_ZONE_VALUE (приоритет зоны под специализацию, 0..1)
| специализация  | repetition | interval | threshold | marathon | easy |
|----------------|-----------|----------|-----------|----------|------|
| 5k             | 0.70      | 1.00     | 0.80      | 0.50     | 0.30 |
| 10k            | 0.60      | 1.00     | 0.85      | 0.60     | 0.30 |
| half_marathon  | 0.40      | 0.70     | 1.00      | 0.90     | 0.50 |
| marathon       | 0.30      | 0.60     | 0.95      | 1.00     | 0.60 |
| speed          | 1.00      | 0.90     | 0.50      | 0.30     | 0.20 |
| fitness        | 0.40      | 0.60     | 0.70      | 0.80     | 0.80 |

Зоны: repetition (скоростная) / interval (МПК) / threshold (ПАНО) / marathon (темповая) / easy (лёгкая).

## Алгоритм recommend_group (по шагам)

```
1. Определить character тренировки (_workout_character).
2. Для КАЖДОЙ группы:
   а) intensity по её темпу относительно порога бегуна
   б) time_to_termination по темпу + восстановлению
   в) quality_volume = intensity × ttt
3. Нормировать quality_volume к [0..1] по всем группам (qvnorm).
4. Для каждой группы:
   pct = usefulness(zone, spec, character) × qvnorm × 100
5. Если is_borderline:
   - для каждой группы посчитать alt_pct: лучший % среди ДРУГИХ специализаций
     (qvnorm не зависит от спец, меняется только usefulness)
   - основная группа = max(pct) по текущей спец
   - альтернатива значима если alt_pct - pct >= 12 (порог отображения)
6. Если НЕ borderline:
   - спец не влияет, основная группа по чистой форме
   - usefulness не тилтит (группы отличаются только «быстрее/медленнее»)
   - вес: _W_FORM_NB=0.58, _W_REC_NB=0.42
```

## Метки групп (из положения на кривой quality_volume)

По положению темпа относительно пика (порога):
- **оптимум** — у порога, и развивает и добежишь (макс quality_volume)
- **тяжело, но реально** — выше порога, ttt падает, но ещё посильно
- **риск схода** — сильно выше порога, ttt→0, не добежит
- **низкий стимул** — ниже порога, intensity мал, «качества» мало
- **слишком легко** — намного ниже

## КОНСТАНТЫ — текущие значения и роль

| Константа | Значение | Роль | Калибровка |
|-----------|----------|------|------------|
| `_USEFULNESS_FLOOR` | **0.72** | ширина влияния спец (0.72..1.0) | ↓ = спец влияет сильнее, больше альтернатив |
| `_INTENSITY_EXP` | 4.0 | крутизна спада ниже порога | ↑ = медленные зоны резче падают |
| `_TTT_TAU` | **28.0** | точка полуобрыва за порогом (сек/км) | ↑ = дальше за порог посильно |
| `_TTT_STEEP` | **5.5** | крутизна обрыва | ↑ = резче отказ за порогом |
| `_TTT_RECOVERY_K` | 0.35 | сила поправки на усталость | ↑ = усталость сильнее сдвигает |
| `_W_FORM_NB / _W_REC_NB` | 0.58 / 0.42 | веса для non-borderline | — |
| порог alt (в коде) | 12 | мин. разница для показа альтернативы | НЕ трогаем пока |

## Калибровка _USEFULNESS_FLOOR (сколько альтернатив показывать)

floor задаёт ширину диапазона usefulness, а значит размах разницы alt_pct − pct.
Цель — 1-2 значимые альтернативы на borderline, без перекоса основного выбора.

| floor | usefulness | вклад спец | разница alt−pct (пример гр.2) | видно альтернатив |
|-------|-----------|-----------|-------------------------------|-------------------|
| 0.80 (было) | 0.80..1.0 | ~1% | 0-1% | 0 (невидимо) |
| **0.72 (сейчас)** | 0.72..1.0 | ~14% | ~29% (гр2 МПК→5k) | 1-2 |
| 0.70 | 0.70..1.0 | ~18% | ~18% | 2-3 |
| 0.65 | 0.65..1.0 | ~25% | ~25% | 2-3 |
| 0.50 (старое) | 0.50..1.0 | ~50% | ~36% | 3-4 (перекос основного) |

ВАЖНО: spec_component зажат ещё и характером (char_v × (0.6+0.4×base)), поэтому
реальный размах меньше «чистого» (1−floor). Цифры в таблице — оценочные, ТОЧНЫЕ
пороги проверять прогоном /workout, а не только аналитически.

История: floor=0.40 (до 0.16.6) давал разброс 12-20% → альтернативы видны, НО спец
слишком явно меняла основной выбор. floor=0.80 (0.16.6+) убрал перекос, но и
альтернативы исчезли. floor=0.72 — компромисс: альтернативы видны, основной выбор
стабилен.

## Что калибровать дальше (на реальных данных)

- `_USEFULNESS_FLOOR` — по факту: сколько альтернатив реально показывается, не перекошен ли основной выбор. Сейчас целимся в 0.72.
- `_TTT_*` — дотюнить по замерам с РАЗНЫХ бегунов (когда пойдут факты тренировок),
  не только по калибровке владельца (ЛП 4:17).
- порог alt=12 — можно подумать позже (пока не трогаем).
