# Тестовое задание для составного повтора (800+200)

> Эталонный пример для доработки «составной повтор: несколько рабочих сегментов
> внутри одного repeat». На нём отлаживаем тестовый скрипт `scripts/test_composite.py`,
> прежде чем переносить правило в боевой `_build_analyze_prompt`.
> Дата тренировки: 2026-06-09 (вторниковая интервальная).

## Текст анонса (как в канале)

**Работа:** 8 серий по 1 км / 200 м
На 1 км набегаем последние 200 м

Группы (отличаются только темпами):
- Группа 1: 800 м — темп 3:30 / 200 м — 40-34 секунды / 200 м — лёгкий бег
- Группа 2: 800 м — темп 3:45 / 200 м — 43-38 секунд / 200 м — лёгкий бег
- Группа 3: 800 м — темп 4:05 / 200 м — 47-42 секунды / 200 м — лёгкий бег
- Группа 4: 800 м — темп 4:40 / 200 м — 53-47 секунд / 200 м — лёгкий бег
- Группа 3.5: промежуточная (если есть)
- Группа 5: медленнее группы 4
- Группа здоровье: бег/ходьба

Примечание: «200 м — 40-34 секунды» = ВРЕМЯ на отрезок (ускорение с прогрессией),
пересчитывается в темп/км. Восстановление 200 м лёгким бегом — ПОСЛЕ связки.

## Как СЕЙЧАС бот разбирает (неверно для Garmin)

Один repeat-блок `8×1000м`, внутреннее «800+200» сворачивается в прогрессию
темпа на километре (work_pace_start→work_pace_end). Для выбора группы по зонам
сойдёт, но Garmin-экспорт получается структурно неправильным.

## Как ДОЛЖНО быть (цель)

structure[] блока 1:
```json
{"block": 1, "type": "repeat", "reps": 8, "recovery_distance_m": 200,
 "work_distance_m": 1000,
 "segments": [
   {"distance_m": 800, "role": "база"},
   {"distance_m": 200, "role": "ускорение"}
 ],
 "purpose": "..."}
```

groups[].blocks[] (пример группы 1) — темп ПО СЕГМЕНТАМ, у каждого свой диапазон
work_pace_start→work_pace_end (ровный = start==end, прогрессия = start!=end):
```json
{"block": 1,
 "segments": [
   {"distance_m": 800, "work_pace_start": "3:30", "work_pace_end": "3:30"},
   {"distance_m": 200, "work_pace_start": "3:20", "work_pace_end": "2:50"}
 ],
 "recovery_pace": "...", "active_recovery": false}
```

Структура говорит «в блоке 1 два сегмента: 800 и 200», группа говорит
«на 800 темп X→W, на 200 темп Y→Z». recovery — на уровне блока (отдых после связки).

## Garmin-референс (целевой экспорт)

`img/references/garmin_composite_rep_DD_20260609.json` — реальный экспорт из Garmin:
один RepeatGroupDTO numberOfIterations=8, внутри ПОДРЯД:
- interval 800 (pace.zone, база) — ВНИМАНИЕ: в экспорте был no.target, это ОШИБКА,
  должен быть pace.zone с базовым темпом;
- interval 200 (pace.zone, ускорение);
- recovery 200 (no.target);
skipLastRestStep=true.

## План доработки (по шагам, обратносовместимо)

Подробно в `IDEAS_BACKLOG.md` → «Составной повтор: несколько рабочих сегментов
внутри одного repeat». Кратко порядок:
1. Промпт/формат segments[] — отлаживаем в `scripts/test_composite.py` (НЕ трогая
   боевой `_build_analyze_prompt`), глазами проверяем разбивку.
2. Отображение `_format_analysis_result` — показать сегменты админу.
3. Выбор группы `recommend_group` / `_group_primary_pace` — определяющий сегмент.
4. `fit_generator` — связка как несколько interval-шагов внутри одного repeat.
Garmin-экспорт на время отладки можно временно отключить, если так проще.
